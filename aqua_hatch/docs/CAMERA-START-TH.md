# AquaHatch 0.4.0 — กล้องในเครื่องและการตรวจนับ

รุ่นนี้รวมฟังก์ชันกล้องจากโค้ดอีกแชทเข้ากับหน้าตรวจนับแบบ 3 ขั้นและการแก้บั๊กช่อง URL ของรุ่น 0.3.1 แล้ว ใช้ source/Gateway ชุด 0.4.0 ให้ตรงกับ APK

## สิ่งที่กดได้ในแอป

1. เปิด **นับลูกปลา** จะเข้าสู่หน้ากล้อง ไม่มีภาพตัวอย่างแสดงแทนภาพจริงโดยอัตโนมัติ
2. ในโหมดทดลอง ปุ่มถ่ายกล้องจริงจะยังไม่พร้อม ใช้ **ใช้ภาพตัวอย่าง** เพื่อทดลองขั้นตอนตรวจแก้และบันทึกได้
3. เมื่อตั้งค่า Gateway และบอร์ดกล้องแล้ว ไป **ตั้งค่า → เครื่องและการเชื่อมต่อ → เครื่องจริง** ใส่ URL Gateway, รหัสเครื่อง และรหัสเข้าถึง
4. กลับหน้ากล้อง รอสถานะ **พร้อมถ่าย** แล้วกด **ถ่ายภาพจากกล้องในเครื่อง** แอปสร้างคำขอใหม่และรอ JPEG ของคำขอนั้น
5. เมื่อได้รับภาพจะแสดงภาพกับเวลาที่เซิร์ฟเวอร์รับ สามารถ **นับด้วยมือ** หรือ **วิเคราะห์ด้วย AI** แล้วเข้าสู่หน้าตรวจนับ เพิ่ม/ลบจุด ซูม ตรวจยืนยัน และบันทึกเข้ารอบฟัก
6. กด **ถ่ายภาพใหม่จากกล้องในเครื่อง** เพื่อถ่ายอีกครั้ง ภาพก่อนหน้าจะถูกล้างตอนเริ่มคำขอใหม่ หากกล้องล้มเหลวจะไม่ใช้ภาพเก่าแทน

นี่คือการถ่ายภาพนิ่งตามคำสั่ง ยังไม่มีวิดีโอสดต่อเนื่อง ภาพและรหัสงานใช้คู่กัน เวลาในแอปเป็นเวลารับภาพที่ Gateway ไม่ใช่เวลาของเซนเซอร์

กล้องมือถือ/เลือกภาพ/เลือกคลิปอยู่ใน **นำเข้าภาพอื่น (ทางเลือก)** จึงไม่สับสนกับกล้องที่ติดในเครื่อง

## การเชื่อมต่อของจริง

เส้นทางคือ **แอป → HTTPS Gateway → MQTT Broker → บอร์ดกล้อง → อัปโหลด JPEG กลับ Gateway → แอป** บอร์ดอัปโหลดใช้ต่อคอมเพื่อแฟลชโปรแกรม ไม่ได้แทน Gateway หรือทำให้กล้องส่งภาพถึงแอปเอง

ตั้งค่าฝั่งเซิร์ฟเวอร์ตาม [คู่มือตั้งค่ากล้อง](../firmware/CAMERA_SETUP.md) และใช้ [ตัวอย่าง environment](../gateway/.env.example) บอร์ดกล้องและบอร์ดควบคุมสามารถแยกกันได้ สถานะกล้องไม่ขึ้นอยู่กับ telemetry ของบอร์ดควบคุม แต่ปุ่มควบคุมปั๊ม/ฮีตเตอร์ยังต้องใช้ข้อมูลเครื่องที่ใหม่และ ACK ตามเดิม

## ESP32-S3 + OV5640 ที่ระบุไว้

- ESP32-S3 คือชิป/ตระกูลบอร์ด ส่วน OV5640 คือเซนเซอร์กล้อง ชื่อนี้ยังบอก GPIO หรือรูปแบบสายแพไม่ได้
- `firmware/camera_node/camera_node.ino` คือโค้ดกล้องรับคำสั่ง MQTT และอัปโหลด JPEG ไม่ใช่เฟิร์มแวร์ควบคุมฮีตเตอร์/ปั๊มทั้งหมด
- คัดลอก `config.example.h` เป็น `config.h` แล้วตั้ง Wi-Fi, บัญชี MQTT ของกล้อง, URL Gateway, root CA และ pin map จากผู้ผลิตบอร์ดรุ่นจริง
- ค่าเริ่มต้น `CAMERA_PINS_CONFIRMED=0` จะหยุด compile จนกรอกและยืนยันขา ไม่ควรคัดลอกขาของบอร์ดยี่ห้ออื่นเพียงเพราะใช้ชิปเดียวกัน
- เลือกขนาด flash/PSRAM ตามบอร์ดจริง คำว่า “S3” อย่างเดียวไม่ยืนยันว่าเป็น N16R8 หรือใช้ OPI PSRAM
- ยังไม่มีไฟล์ firmware `.bin` ที่รับรองให้แฟลชบนบอร์ดที่ยังไม่ทราบรุ่น

ไดรเวอร์ทางการรองรับ ESP32-S3 และ OV5640 และระบุความต้องการ PSRAM สำหรับภาพ JPEG ความละเอียดสูง: [Espressif esp32-camera](https://github.com/espressif/esp32-camera)

## คำสั่งควบคุมใช้ได้จริงแค่ไหน

| ส่วน | สิ่งที่มีในชุดนี้ | สิ่งที่ต้องยืนยันเพิ่ม |
| --- | --- | --- |
| แอปสั่งถ่าย/รับภาพ | HTTP API, ตรวจรหัสงาน, โหลด JPEG และแสดงเวลา | ลองกับกล้องและอินเทอร์เน็ตจริง |
| Gateway จัดการงาน | สิทธิ์เข้าถึง, token เฉพาะงาน, MQTT command, เก็บภาพส่วนตัว, timeout | ตั้ง server/Broker/TLS ของเจ้าของเครื่อง |
| เฟิร์มแวร์กล้อง | source สำหรับ ESP32-S3 และ driver กล้อง | pin map, PSRAM, สายแพ, certificates, แฟลชและทดสอบบอร์ด |
| ควบคุมปั๊ม/ฮีตเตอร์ | แอป/Gateway ส่งคำสั่งและรอ ACK มีเครื่องจำลองสำหรับทดสอบ | เฟิร์มแวร์บอร์ดควบคุมและวงจรจริงตาม MQTT protocol |
| AI นับลูกปลา | จุดเชื่อมโมเดลและตรวจแก้ผล | weights ที่ฝึกกับลูกปลาจริงและผลวัดความแม่นยำ |

ถ้าไม่ได้ตั้ง `LARVAE_MODEL_PATH` เซิร์ฟเวอร์จะตอบว่ายังไม่มีโมเดล ภาพยังเปิดนับจุดด้วยมือได้ ชุดนี้ไม่สร้างผล AI ปลอม และภาพตัวอย่างจะระบุว่าเป็นการจำลองเสมอ

อุปกรณ์ที่กล่าวถึงในแชทอีกชุดคือ DS18B20, ปั๊มน้ำ 12V ผ่าน MOSFET และฮีตเตอร์ 220V ผ่านรีเลย์ ยังไม่ได้รับรุ่นเต็มหรือผังสาย จึงยังไม่กำหนด GPIO ให้ส่วนเหล่านี้ วงจรฮีตเตอร์ต้องมีตัวตัดร้อนเกินที่ทำงานอิสระจาก ESP32 และให้ผู้ชำนาญตรวจส่วนไฟบ้านก่อนจ่ายไฟ

## ตรวจรับกับบอร์ดจริง

1. ตรวจ pin map และเริ่มจากเปิดกล้องได้โดยยังไม่ต่อโหลดปั๊ม/ฮีตเตอร์
2. ถ่ายวัตถุ A แล้วเปลี่ยนเป็น B และถ่ายใหม่ ต้องได้คนละรหัสและคนละภาพ
3. ถอดไฟกล้อง ต้องแสดงออฟไลน์/หมดเวลาและไม่แสดงภาพเดิมเป็นภาพใหม่
4. เปลี่ยนเครื่อง/เซิร์ฟเวอร์ระหว่างรอ ภาพจากงานเดิมต้องไม่กลับมาในเครื่องใหม่
5. กดนับด้วยมือ ตรวจแก้ และบันทึก ให้ตรวจที่มาว่าเป็นภาพกล้องจริง
6. จึงทดสอบคำสั่งควบคุมกับเฟิร์มแวร์บอร์ดหลัก ตรวจ ACK และเงื่อนไขหยุดเมื่อข้อมูลหรือเซนเซอร์หาย ก่อนต่อโหลดจริง

ผลตรวจซอฟต์แวร์ของ APK ชุดนี้อยู่ที่ `VERIFICATION.md` การคอมไพล์ผ่านหรือการใช้กล้องจำลองยังไม่ใช่ผลทดสอบฮาร์ดแวร์จริง
